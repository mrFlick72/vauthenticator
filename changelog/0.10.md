# VAuthenticator 0.10

## :star: New Features

- password lifecycle: password TTL, expiry notification and mandatory renewal of an expired password [#298](https://github.com/mrFlick72/vauthenticator/issues/298)
- block an account when consecutive failed logins exceed a threshold (Failed-Login Lock) [#211](https://github.com/mrFlick72/vauthenticator/issues/211)
- events carry the request context (IP, user agent, session reference) [#215](https://github.com/mrFlick72/vauthenticator/issues/215)
- SMS template API [#290](https://github.com/mrFlick72/vauthenticator/issues/290)
- delete/revoke an associated MFA device [#338](https://github.com/mrFlick72/vauthenticator/issues/338)
- MFA association failures reported by reason instead of a generic 500 [#339](https://github.com/mrFlick72/vauthenticator/issues/339)
- MFA device listing returns only associated devices [#343](https://github.com/mrFlick72/vauthenticator/issues/343)
- POST /api/mfa/associate returns the associated device [#344](https://github.com/mrFlick72/vauthenticator/issues/344)
- management ui router moved from HashRouter to BrowserRouter [#325](https://github.com/mrFlick72/vauthenticator/issues/325), [#356](https://github.com/mrFlick72/vauthenticator/issues/356), [#357](https://github.com/mrFlick72/vauthenticator/issues/357)
- management ui opens the Session expired dialog when an admin API call returns 401 [#420](https://github.com/mrFlick72/vauthenticator/issues/420)
- Playwright end-to-end tests for management ui against auth-server [#355](https://github.com/mrFlick72/vauthenticator/issues/355)
- tenant setup saves the default email and SMS templates, no manual upload needed [#437](https://github.com/mrFlick72/vauthenticator/pull/437)
- tenant setup saves the Default Pages (login, MFA, signup, password and error pages), built into the jar by Maven, no manual upload needed; the setup also works on a new tenant with empty storage [#438](https://github.com/mrFlick72/vauthenticator/issues/438)

## :warning: Upgrade notes

- **Database.** The schema only runs on an empty database, so an existing 0.9 PostgreSQL database needs, before upgrading:

  ```sql
  CREATE TABLE PASSWORD_LIFECYCLE_RULES
  (
      user_name                   varchar(255) not null,
      evaluation_interval_seconds bigint       not null,
      created_at                  TIMESTAMP    not null,
      last_evaluation_date        TIMESTAMP,
      action                      varchar(255) not null,
      primary key (user_name, action)
  );
  ALTER TABLE ACCOUNT ADD COLUMN locked_until TIMESTAMP WITH TIME ZONE;
  ALTER TABLE TICKET ADD COLUMN code_attempts integer NOT NULL DEFAULT 0;
  ```

  `PASSWORD_LIFECYCLE_RULES` backs the password lifecycle [#298](https://github.com/mrFlick72/vauthenticator/issues/298), `ACCOUNT.locked_until` the Failed-Login Lock [#211](https://github.com/mrFlick72/vauthenticator/issues/211) and `TICKET.code_attempts` the MFA association code count [#339](https://github.com/mrFlick72/vauthenticator/issues/339).
- **DynamoDB removed.** PostgreSQL is the only persistence; DynamoDB data is not migrated. [#402](https://github.com/mrFlick72/vauthenticator/issues/402)
- **vauthenticator chart values.**
  - `application.profiles`: drop `dynamo` (default is now `kms`); `application.datasource.url` is required.
  - `application.dynamoDb.*` and `application.aws.dynamodb` are removed.
  - Caches move to `application.cache.<account|role|clientApplication>.{enabled,ttl,name}` and are off by default; `application.dynamoDb.role.protectedFromDelete` becomes `application.role.protectedFromDelete`.
  - `application.assetServer.onS3.enabled` is removed: auth-server never read it.
  - The `httpRoute.gatewayClassName` default is now `traefik` (it was the typo `traeefik`).
  - With `application.documentRepository.engine: file-system`, `fsBasePath` must be an absolute path: the chart mounts an `emptyDir` there, or the PersistentVolumeClaim in `application.documentRepository.fileSystem.existingClaim`, so tenant setup can write the default templates and pages. [#434](https://github.com/mrFlick72/vauthenticator/issues/434)
  - New, with defaults: `application.password.lifeCycle.cron`, `application.ticket.ttl.*`, `application.login.failedLoginLock.{threshold,duration}`, and `httpRoute.parentRefs` to attach the HTTPRoute to an existing Gateway. [#434](https://github.com/mrFlick72/vauthenticator/issues/434)
- **management-ui chart values.** `application.authenticationCheckInterval` is removed. [#425](https://github.com/mrFlick72/vauthenticator/issues/425)
- **Templates and pages of an existing tenant.** Tenant setup is for a new tenant only. An existing tenant gets the new SMS template by saving it through `PUT /api/sms-template` or the management UI (SMS MFA challenges fail until it exists) [#290](https://github.com/mrFlick72/vauthenticator/issues/290), and its Default Pages are uploaded to the document store by the operator [#439](https://github.com/mrFlick72/vauthenticator/issues/439).
- **Tickets issued before the upgrade.** MFA enrollments in progress must be started again and email-verification links requested again; reset-password links keep working only until 5 minutes after they were sent. [#339](https://github.com/mrFlick72/vauthenticator/issues/339)
