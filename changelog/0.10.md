# VAuthenticator 0.10

## :star: New Features

- password lifecycle: password TTL, expiry notification and mandatory renewal of an expired password [#298](https://github.com/mrFlick72/vauthenticator/issues/298)
- block an account when consecutive failed logins exceed a threshold (Failed-Login Lock) [#211](https://github.com/mrFlick72/vauthenticator/issues/211)
- events carry the request context (IP, user agent, session reference) [#215](https://github.com/mrFlick72/vauthenticator/issues/215)
- SMS template API [#290](https://github.com/mrFlick72/vauthenticator/issues/290)
- delete/revoke an associated MFA device [#338](https://github.com/mrFlick72/vauthenticator/issues/338)
- MFA association failures reported by reason instead of a generic 500 [#339](https://github.com/mrFlick72/vauthenticator/issues/339)
- MFA device listing returns only associated devices [#343](https://github.com/mrFlick72/vauthenticator/issues/343)
- POST /api/mfa/associate returns the associated device [#344](https://github.com/mrFlick72/vauthenticator/issues/344)
- management ui router moved from HashRouter to BrowserRouter [#325](https://github.com/mrFlick72/vauthenticator/issues/325), [#356](https://github.com/mrFlick72/vauthenticator/issues/356), [#357](https://github.com/mrFlick72/vauthenticator/issues/357)
- management ui opens the Session expired dialog when an admin API call returns 401 [#420](https://github.com/mrFlick72/vauthenticator/issues/420)
- Playwright end-to-end tests for management ui against auth-server [#355](https://github.com/mrFlick72/vauthenticator/issues/355)

## :lock: Security

- authorization on Role/Group admin APIs (VA-SEC-01) [#362](https://github.com/mrFlick72/vauthenticator/issues/362)
- authorization on admin account APIs (VA-SEC-01) [#364](https://github.com/mrFlick72/vauthenticator/issues/364)
- only an Administrator grants or removes administration (VA-SEC-15) [#365](https://github.com/mrFlick72/vauthenticator/issues/365)
- only an Administrator manages an Administrator account [#428](https://github.com/mrFlick72/vauthenticator/issues/428)
- granular admin scopes on client apps granted by any client app writer, full access reserved to Administrators [#429](https://github.com/mrFlick72/vauthenticator/issues/429)
- GET /api/mfa/enrollment requires the mfa:enrollment scope [#340](https://github.com/mrFlick72/vauthenticator/issues/340)
- keys API authorization moved in controller [#367](https://github.com/mrFlick72/vauthenticator/issues/367)
- email template API authorization moved in controller (VA-SEC-14) [#368](https://github.com/mrFlick72/vauthenticator/issues/368)
- password APIs authorization moved in controller [#369](https://github.com/mrFlick72/vauthenticator/issues/369)
- dependency vulnerabilities fix (Jinjava, BouncyCastle and Dependabot sweep) [#349](https://github.com/mrFlick72/vauthenticator/issues/349)

## :art: Refactoring

- remove DynamoDB support: PostgreSQL only, opt-in caches with evict-on-write [#402](https://github.com/mrFlick72/vauthenticator/issues/402)
- remove redundant WebSecurityConfig scope rules for /api/sign-up/welcome and /api/verify-challenge [#370](https://github.com/mrFlick72/vauthenticator/issues/370)
- drop dead session param from WelcomeEMailEndPoint [#374](https://github.com/mrFlick72/vauthenticator/issues/374)
- remove the unused AUTHENTICATION_CHECK_INTERVAL setting from management ui and helm chart [#425](https://github.com/mrFlick72/vauthenticator/issues/425)
- MFA documentation update [#341](https://github.com/mrFlick72/vauthenticator/issues/341)
